# 🌐 API Design & Implementation

> **Group Skill** — Orchestrates sub-skills for designing and building a new API.
> Activate by saying: "Design an API" or "build a REST API"

## When to Use

- Designing and building a new API
- Need to choose REST vs GraphQL vs tRPC
- Setting up API documentation and monitoring

## Step-by-Step Workflow

### Step 1: Decision
**Skill**: `api-patterns`
- Choose REST vs GraphQL vs tRPC
- Evaluate trade-offs
- Select appropriate protocol

### Step 2: Design
**Skill**: `api-design-principles` / `openapi-spec-generation`
- Define API contracts
- Create OpenAPI/Swagger specs
- Plan versioning strategy

### Step 3: Validation
**Skill**: `zod-validation-expert` / `pydantic-models-py`
- Implement input validation
- Define request/response schemas
- Handle error cases

### Step 4: Auth
**Skill**: `auth-implementation-patterns` / `api-security-best-practices`
- Secure API endpoints
- Implement authentication
- Configure authorization

### Step 5: Backend
**Skill**: `python-fastapi-development` / `nodejs-backend-patterns` / `golang-pro`
- Implement API endpoints
- Connect to data sources
- Handle business logic

### Step 6: Testing
**Skill**: `api-testing-observability-api-mock`
- Write API tests
- Create request mocks
- Test error scenarios

### Step 7: Documentation
**Skill**: `api-documentation` / `api-documentation-generator`
- Generate API docs
- Create usage examples
- Document edge cases

### Step 8: Monitoring
**Skill**: `azure-monitor-opentelemetry-ts` / `prometheus-configuration`
- Set up API observability
- Track latency and errors
- Configure alerting

## Completion

API is designed, built, tested, documented, and monitored. 🌐
